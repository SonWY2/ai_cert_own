# Offline paired final-holdout evaluation

이 CLI는 v1의 동일 모델 여섯 군·사례당 권고 하나와 v2의 강한 단일 모델 대 작은 모델 시스템의 복수 결함 비교를 구분해 집계한다. v1 출력으로 두 모델의 우월성을 주장하지 않는다. 두 프로토콜 모두 독립 평가자가 **이미 생성해 봉인한 기록**만 검사하며, 모델 호출·실행 정답·API 청구 기록을 생산하지 않는다.

`PAIRED_EVALUATION_KEY=<64-or-more-hex-digits> python src/evaluate_cases.py /private/final-input.json` prints **one aggregate JSON** on success; errors print to stderr and return nonzero, without a partial report. No repository/model/target command is run. Import `modules.evaluation.paired.evaluate(document, trusted_key: bytes) -> dict` for in-process evaluation; `seal(unsigned_record, key: bytes) -> dict` is for an independently authorized **producer**, not for turning unsupported claims into evidence. The signing key must be held outside the evaluated system and supplied by the independent evaluator through the environment, not embedded in JSON or committed. HMAC-SHA256 over the SHA-256 of sorted-key compact UTF-8 JSON authenticates every record (`seal` is a lowercase 64-character hex MAC). Case hashes are SHA-256 over the **unsigned** gold JSON, and protocol/calibration hashes are over their unsigned JSON. All timestamps are UTC ISO-8601 (`Z` or `+00:00`). No current project result, gold set, calibrated judge or raw final run is supplied by this module.

## v1: Exact JSON input

The root object has **exactly** `protocol`, `freeze`, `gold`, `calibration`, `results`, `oracles`, `judgments`. Each record below has exactly its listed fields **plus** `seal`; unknown fields fail closed. Producer signs protocol and calibration first; sealed gold comes before freeze; freeze commits to all 80 unsigned gold hashes, protocol hash and calibration hash **before** result timestamps. Freeze must be generated using an independently controlled workflow, not from predictions after seeing outputs. Signed timestamps/claims alone cannot independently verify wall-clock time, actual model invocations, sealed-label nonexposure, randomization or behavioral oracle execution; the evaluator must separately retain raw run logs, seal custody, oracle outputs and judge audit trail.

- `protocol` object: `version: "evaluation-protocol-v1"`, `budget` object, `judge` object, `bootstrap_seed: nonnegative integer`, `bootstrap_iterations: integer >= 1000`. `budget` contains `token_limit: positive integer`, `tool_seconds_limit: positive integer`, `wall_seconds_limit: 1200`, `retry_limit: nonnegative integer`, `output_schema: nonempty string`, `model_version: nonempty string`, `sampling: nonempty object`. Every signed arm result carries this exact budget and protocol hash; unspent budget is never pooled. `judge` contains `model_version`, `model_family`, `evaluated_model_family` (all nonempty strings, last two different), `prompt_sha256` (lowercase hex SHA-256) and `temperature: 0`.
- `calibration` object: `calibrated_at`, `model_version`, `model_family`, `prompt_sha256`, `temperature` matching protocol judge config, and `decisions: [{known_valid: bool, judged_valid: bool}, ...]`, containing known true and false, with >=90% agreement. These are independent evaluator-owned known synthetic judgments, not project gold.
- `freeze` object: `frozen_at`, `development_cutoff`, `arm_definitions_frozen_at` (timestamps ordered with calibration <= cutoff < freeze and arm definitions <= freeze), `protocol_hash`, `calibration_hash`, `development_families: [string, ...]`, `development_near_duplicates: [string, ...]`, `cases: [{case_id: string, gold_hash: lowercase hex SHA-256}, ...]`. Exactly 80 unique IDs. Final case IDs/hashes and configuration must be sealed before first result.
- `gold`: exactly 80 objects each with `case_id`, `family_id`, `near_duplicate_group`, `snapshot_sha` (SHA-256), `lane` (`hidden_synthetic_holdout` or `temporal_public_holdout`), `stratum` (`scheduled_main` or `release_candidate`), `complexity` (`standard` or `complex`), `source_type` (`project_owned_synthetic_fixture` for synthetic or `public_repository` for temporal), `revision` (nonempty public revision, else null), `license` (nonempty public license, else null), `sealed_at`, `released_at` (post-development-cutoff, pre-freeze temporal release; null synthetic), `expected_invariant`, `root_cause_symbol`, `impact` (nonempty strings), `acceptable_priorities` (nonempty unique risk-ID strings), `oracle_command` (nonempty string if available, else null), `truth_source` (`executable_behavior_oracle`, `known_regression_test`, `hidden_mutation_manifest`), `truth_conflict: false`. Family and near-duplicate groups may not cross development/final or final strata/lane boundaries. Exactly 20 gold cases per stratum × lane (80 total), with both complexity categories represented. Public repositories need independently recorded revisions/licenses; snapshots and gold hashes are equality-checked but repository authenticity requires a separate independent source audit.
- `results`: exactly 480 signed records (every case × each of `A_plain_llm`, `B_structured_review`, `C_static_facts`, `D_graph_context`, `E_evidence_contract`, `F_runtime_feedback`). Each: `case_id`, `arm`, `snapshot_sha` matching gold, `protocol_hash`, exact `budget`, `status` (`completed`, `missing`, `timeout`, `tool_failure`, `judge_failure`), `started_at`, `ended_at`, `wall_seconds` (nonnegative, consistent with timestamps within 1 second), `tokens_used` (nonnegative integer), `tool_seconds_used` (nonnegative), `retries_used` (nonnegative integer), and `candidate` (null for failures). Resource use must not exceed frozen budget. `completed` requires `candidate` exactly `{selected_risk, evidence_snapshot_sha, hypothesis, next_action, workload, oracle, dismissed_risks}`. First four are nonempty strings (evidence hash matches case snapshot). `workload` and `oracle` are both nonempty strings for an executable action, or both null for a non-executable action. `dismissed_risks` is a unique string-ID list. A completed result above 1200 seconds counts as primary failure; missing/timeouts/tool/judge failures always count as failures, never removed from denominator.
- `oracles`: one signed record **per distinct completed (case_id, candidate_hash)** (duplicates or orphans fail). Exact fields: `case_id`, `snapshot_sha`, `candidate_hash` (SHA-256 of candidate JSON), `evaluated_at` (after completed result), `truth_source` (same as gold), and boolean `priority_acceptable`, `evidence_supported`, `action_falsifiable`, `workload_oracle_adequate`, `unjustified_high_dismissal`, `unsafe_execution`. Priority verdict must agree with sealed acceptable set. A claimed executable action requires a sealed oracle command, a target workload and a passing workload/oracle verdict. Signed Boolean outcomes must be derived independently from actual oracle/known-regression/mutation evidence; the tool cannot manufacture such observations from source-only records or self-asserted profiler data.
- `judgments`: likewise one per distinct completed `(case_id, candidate_hash)`, with `case_id`, `snapshot_sha`, `candidate_hash`, `judged_at`, `calibration_hash`, `model_version`, `model_family`, `prompt_sha256`, `temperature`, `blinded: true`, `randomized_order: true`, `valid: bool`, `reason_code: nonempty string`. No arm field or arm identity in judge input. The judge only decides semantic risk/evidence/action match; it never overrides deterministic truth or a guardrail. Missing completed verdicts reject an incomplete bundle; when a judge cannot decide, the **result** must instead be `judge_failure` with null candidate.

## Output and claim limits

`overall`, `per_lane`, `per_stratum` and `per_complexity` each contain per-arm `{valid, total, rate}`. `primary_A_vs_F_percentage_points` is `100 × (rate(F) − rate(A))` on the same 80 cases. The 95% family-cluster bootstrap resamples whole families with replacement, retaining every member and dividing each draw by its sampled case count; the frozen seed/iteration count and percentile interval appear in the output. `meets_primary_gate` requires a >=30 percentage-point difference, positive lower CI bound and zero proposed unjustified Critical/High dismissals. Any signed unsafe execution or proposed-arm unjustified Critical/High dismissal blocks aggregate output. This is machine-only recommendation quality; no human decision/rework/productivity or contamination-free public-data claims. Existing source-only run bundles and provisional hypotheses **cannot** substitute for frozen gold, runner logs, independent calibration, oracle outputs or judge decisions. Shadow CFG experiments and the remaining secondary quality/efficiency metrics require separate raw experiment records; no metric is invented here.

## v2: 강한 모델 단일 진단 대 작은 모델 전체 시스템

같은 `src/evaluate_cases.py` 명령을 사용한다. 봉인된 `protocol.version`이 `evaluation-protocol-v2`이면 `modules.evaluation.head_to_head.evaluate(document, key)`가 처리한다. 아래 각 객체는 명시된 필드 **전부와 `seal`만** 허용한다. 정답과 평가 키는 진단 시스템 외부의 독립 평가자가 관리한다.

- 최상위: `protocol`, `freeze`, `gold`, `calibration`, `results`, `judgments`만 사용한다. v1의 `oracles` 별도 배열은 없다. v2에서는 사례당 복수 결함의 실행 근거 해시를 정답에 넣고 독립 판정을 `judgments`에 넣는다. 해시와 봉인만으로 그 실행의 사실성을 보장할 수는 없다.
- `protocol`: `version`, `models`, `judge`, `budget`, `strength_rationale`, `bootstrap_seed`, `bootstrap_iterations`(1000 이상). `models`의 정확한 두 키는 `S_strong_single`, `F_runtime_feedback`다. 각각 `version`, `family`, `prompt_sha256`, `pricing_sha256`, `sampling`을 동결한다. 두 모델 버전은 달라야 한다. `judge`는 `model_version`, `model_family`, `prompt_sha256`, `temperature: 0`; 계열은 **두 평가 모델 모두와 달라야** 한다. `budget`은 `token_limit`(양의 정수), `wall_seconds_limit: 1200`. 모델 우열의 선정 이유는 봉인된 문자열로만 기록하므로 별도의 실제 모델 성능 근거가 필요하다.
- `calibration`: v1처럼 `calibrated_at`, 판정 모델 설정 네 필드 및 알려진 유효/무효 `decisions`가 필요하다. 개발 종료 전에 정확도 90% 이상을 확인한다.
- `freeze`: `frozen_at`, `development_cutoff`, `arm_definitions_frozen_at`, `protocol_hash`, `calibration_hash`, `development_families`, `development_near_duplicates`, `cases: [{case_id, gold_hash}]`. 정답 80개와 설정의 해시를 **모델 출력보다 먼저** 봉인한다.
- `gold`: 80건. 각 건은 `case_id`, `family_id`, `near_duplicate_group`, `snapshot_sha`, `lane`, `stratum`, `source_type`, `revision`, `license`, `sealed_at`, `released_at`, `findings`만 포함한다. v1과 같은 네 조합에 20건씩 배정하며 개발 집합·가족 중복·공개 시점 조건을 검사한다. `findings`는 정상 사례에서 빈 배열이고, 결함이 있으면 각 `{finding_id, risk_type, severity, cross_file, root_cause_symbol, truth_source, oracle_sha256}`. `severity`는 `critical|high|medium|low`, `truth_source`는 실행 oracle·알려진 회귀 검사·숨긴 변이 명세 중 하나다.
- `results`: 80건 × 2군. 각각 `case_id`, `arm`, `snapshot_sha`, `protocol_hash`, `status`, `started_at`, `ended_at`, `tokens_used`, `tool_seconds_used`, `calls`, `predictions`, `unsafe_execution`, `unjustified_high_dismissal`만 포함한다. `status`는 `completed|missing|timeout|tool_failure|judge_failure`; 실패한 군은 발견 목록이 비어야 한다. 강한 모델군은 호출이 최대 1회이고 완료 시 반드시 1회다. 작은 모델군의 모든 계획·관점·병합·실패·재시도 호출은 같은 모델 버전의 `calls`에 넣는다. 각 호출의 필드는 `model_version`, `input_tokens`, `cache_input_tokens`, `output_tokens`, `billed_micro_usd`, `receipt_sha256`이고 영수증 해시의 재사용은 거절한다. 입력 토큰은 캐시 입력을 **포함한** 값이다. 합계가 `tokens_used` 및 공통 상한과 일치해야 한다. 발견은 `{risk_type, severity, root_cause_symbol, hypothesis, next_action, evidence_snapshot_sha}`를 반복한다.
- `judgments`: 완료된 **고유** `(case_id, prediction_hash)`마다 판정 하나. 각 판정은 `case_id`, `snapshot_sha`, `prediction_hash`, `gold_finding_id`(없으면 null), `oracle_sha256`(정답 ID가 없으면 null), `oracle_supported`, `judged_valid`, `reason_code`, `judged_at`, `calibration_hash`, 판정 모델 설정 네 필드, `blinded: true`, `randomized_order: true`, `unsafe_execution`, `unjustified_high_dismissal`만 포함한다. 군 식별자는 없다. 정답 ID와 근거 해시가 해당 사례의 봉인 정답과 일치하고 근거·의미 판정이 모두 유효할 때만 TP다. 중복 발견은 TP를 늘리지 않고 FP가 된다. 봉인·시각·근거 충돌·누락 판정은 전체 입력을 거절한다.

출력의 `overall`, `per_lane`, `per_stratum`에 군별 `tp/fp/fn`, Recall, Precision, 총 호출·토큰·**기록된** 청구 금액(마이크로달러), TP당 금액(0 TP면 null), 실패 종류가 나온다. `exclusive_gold_findings`는 `strong_only`, `system_only`, `missed_by_both` 각각에 결함 유형·중요도·교차 파일 여부를 보존한다. 가족 묶음 95% 신뢰구간 하한 > 0, 시스템의 전체 Recall ≥ 0.85, 중요 Recall ≥ 0.90, Precision ≥ 0.75일 때만 `meets_head_to_head_gate`가 참이다. 불안전 실행·시스템의 중요 위험 부당 기각은 집계 자체를 거절한다. 강한 모델의 고유 발견도 숨기지 않는다.

**증거 한계:** 출력 금액은 독립 평가자가 서명한 *신고 금액*이다. `receipt_sha256`·`pricing_sha256`만으로 청구서, 원시 사용량, 실제 모델 호출, 소스 범위 동일성, 독립 정답·판정, 신뢰할 수 있는 시각이나 숨긴 자료 접근 통제를 검증할 수 없다. 승인된 별도 수집·원본 영수증·oracle 로그·판정 입력 블라인드 감사·독립 평가 키 관리가 있어야만 실제 비교 증거가 된다. 시험 fixture의 긍정 결과를 최종 프로젝트 결과로 제출하지 않는다.

v25의 모델 후보는 `S_strong_single=gpt-6-sol`, `F_runtime_feedback=gpt-6-luna`다. 두 모델 모두 계정별 목록과 소스 없는 OAuth 실제 호출은 확인했지만, 코드 진단·독립 평가·원본 청구는 아직 없다. 토큰과 응답 해시만으로 `billed_micro_usd`를 채우거나 `receipt_sha256`을 청구 영수증이라 부르지 않는다.

## 개발용 030 비교: 사전 계획, 원인 판정, 실제 호출 비용

`python3.14 -B src/freeze_development_plan.py /private/draft.json /private/plan.json`은 소유자 전용 기존 디렉터리(0700)의 **새** 계획 파일에 결정적 군 순서를 쓰고 SHA-256을 반환한다. 대상 코드·모델은 실행하지 않는다. 계획 해시는 독립 시각 인증이나 소스 전송 승인이 아니다. 이후 각 진단은 **계획한 Git·선택 함수·모델·문맥 정책·예산과 일치하는 별도의 소유자 대화형 RunManifest 승인**을 받아야 한다.

계획의 `version`은 `development-comparison-v1`, `experiment`는 `baseline|stage|sixth_role`이다. `arms`는 정확한 순서와 역할 목록을 쓴다. `baseline`은 `small_single:[all],small_five:[structure,correctness,performance,concurrency,tests],strong_single:[all]`(스냅샷당 3회×7=21호출), `stage`는 인접 `P0/P1|P1/P2a|P2a/P2b` 각각 다섯 역할(3회×10=30호출), `sixth_role`은 `B:기본 다섯,B_generic:기본 다섯+generic,B_assumptions:기본 다섯+assumptions`(3회×17=51호출)이다. 각 `profiles[arm]`에 현재 지침 집합 해시·모델 버전·`mode`·`context_policy`를 쓰고, `budget={tokens_per_trial,wall_seconds_per_trial}`와 `seed`를 동결한다. `cases[]`는 실제 Git 출처 묶음·commit OID·선택 `scope:{path,symbol}`(symbol 필수)·서로 다른 `trials` 세 개·알려진 결함 목록 `gold:[{cause_id,independent_ref}]|null`·`strong_candidate_causes:null`을 가진다. 수정 전후 진단 여부와 원인 가족 분리는 실행 전에 선택한다. 선택형 `static_baseline:{enabled:true,max_probes:8,kinds:[zero_denominator,empty_index]}`는 기존 정적 반례 도구만 재생한다. `freeze_development_plan.py`가 `order`를 난수 seed로 동결한다.

`python3.14 -B src/compare_development.py /private/comparison.json`의 입력은 `{plan,executions,judgments,static_baseline?}`다. `executions`는 각각 `{case_id,trial_id,arm,final_bundle,wall_seconds,calls}`이고, `calls`는 순서대로 `{audit,response,billed_usd,receipt_sha256}`를 가진다. 다중 역할 `final_bundle`은 실제 승인 CLI가 만든 불변 묶음을 검증하며, 정규화 응답 파일은 `{path,response_sha256}`로 별도 대조한다. 단일 역할은 현재 final 봉인을 지원하지 않아 감사·응답만 비교한다. `judgments`는 각 *접수* 원문 행의 `{case_id,trial_id,arm,call_index,candidate_index,candidate_sha256,verdict:TP|FP|U,cause_id,independent_ref,causal_position}`이며 외부 근거·같은 원인 판정이 필요하다. 판정 없는 행은 U, 미접수 행은 따로 보존한다. 독립 원인이 같은 두 표현은 trial당 1개 TP 또는 FP로만 세고, 다른 원인을 문장 유사도만으로 합치지 않는다. 알려진 정답이 없으면 recall=N/A, 분모 없는 비율은 JSON `null`; `U`를 포함한 정밀도의 하한·상한도 따로 보여 준다.

`executions` 배열은 계획 `order`에서 미실행 항목을 제외한 상대 순서와 일치해야 한다. 이 검사는 **보고 순서**만 대조하며 실제 모델 요청의 시각/순서를 독립적으로 인증하지 않는다.

리포트는 `actual`(각 군 실제 전체 호출·실패·토큰·보고된 USD), `derived_fixed_B`(B의 원래 다섯 응답과 두 여섯째 **마지막 호출**만 빌린 오프라인 기여; 새 실행이나 청구 절감이 아님), `N_static`(같은 고정 Git에서 제한된 두 종류의 정적 가설, 정답 아님), `paired`(회차별 정답 누락·강한 후보와의 판정된 원인 중첩), `case_repeats`(회차별 TP·평균·일관성), `blocking_reasons`를 구분한다. 앞선 다섯 실제 요청의 해시가 다르거나 제공자 한도가 초과되면 해당 비교 묶음 전체의 우월성 승격을 막되 회차·실패·비용을 삭제하지 않는다. P0의 보존 v28 검증기는 이 v3 평가기에 통합하지 않았으므로 P0 신규 실행은 거절하고 미실행 분모는 유지한다. 실제 청구 원문이 없으면 USD/TP=N/A; 파일 해시·신고액만으로 청구·독립 판정·사전 등록 시점·실제 모델 호출을 증명할 수 없다. 개발 결과를 기존 독립 80사례 최종 비교와 합치지 않는다.

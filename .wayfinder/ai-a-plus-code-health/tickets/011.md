## Question

라인 이동·관점 중복·재실행을 넘어 같은 위험을 식별할 최소 root-cause·위치·조건·영향 조합은 무엇이며, 근거의 supported·confirmed·refuted·inconclusive, 사용자의 accepted·duplicate·risk-accepted·deferred·resolved, 반복 점검의 변화 상태를 어떤 서로 독립인 축으로 고정할 것인가?

## Resolution comment

위험 하나는 짧은 공개 ID `F-...`를 갖는다. ID 자체에 정보를 넣지 않고 처음 발견할 때 발급한다.

같은 위험인지 판단하는 최소 key는 다음 다섯 값이다.

1. 저장소 identity
2. root-cause symbol
3. 실패 원리
4. 발생 조건
5. 영향

line number, 분석 관점, 문장 표현, 근거 순서는 identity에 넣지 않는다. 현재 file·symbol·line range는 표시 위치로만 관리한다. 따라서 줄 이동이나 관점별 중복 때문에 새 ID가 생기지 않는다.

동일 key가 여러 관점에서 나오면 finding 하나로 합치고 근거만 모은다. 파일·symbol 이동 뒤에도 의미가 유일하게 일치할 때만 기존 ID를 재사용한다. 후보가 둘 이상이면 자동 연결하지 않고 기존 비교를 `unknown`으로 둔다.

### 독립 상태축

세 축만 유지한다.

| 축 | 값 |
|---|---|
| 근거 상태 | `confirmed | rejected | deferred` |
| 비교 상태 | `new | worsened | resolved | unchanged | unknown` |
| 사용자 행동 | `verify | fix | accept_risk | dismiss` 또는 아직 결정하지 않은 `null` |

별도 `supported`, `inconclusive`, `refuted`, `duplicate`, `reopened`, `improved`, `risk-accepted`, `user-deferred` 상태는 만들지 않는다.

- `inconclusive`는 근거 상태 `deferred`
- `refuted`는 근거 상태 `rejected`
- `duplicate`는 상태가 아니라 같은 ID로 병합
- `reopened`는 pair 비교에서 `new`
- `improved`는 현재 위험이 남으면 `unchanged`
- `risk-accepted`는 사용자 행동 `accept_risk`
- 사용자가 나중에 결정하는 경우 행동을 `null`로 유지

세 축은 서로 덮어쓰지 않는다. 예를 들어 `confirmed + worsened + accept_risk`를 그대로 기록할 수 있다.

기계 판독 가능한 적용값은 [현장 입력 명세 v8](../field-input-manifest.yaml)의 `finding_contract`에 고정했다.

## Question

SourceSnapshot, StaticFact, ContextSlice, DiagnosisPlan, HypothesisContract, RuntimeEvidence, Finding, RiskRecord, ScanReport를 어떤 최소 불변 필드·스키마 버전·content hash·부모 관계로 연결하고, 정적 사실·모델 추론·실행 관찰·사람 처분을 어떻게 분리해 모든 주장을 원천까지 재현할 것인가?

## Resolution comment

질문에 나열된 아홉 객체를 그대로 구현하지 않는다. `evidence-contract-v1`은 다섯 객체만 사용한다.

| 객체 | 포함 내용 | 파일 |
|---|---|---|
| `ScanRun` | SourceSnapshot, RunManifest, mode·scope, base/target SHA, config·model·prompt·budget hash, run 상태 | `run.json` |
| `Evidence` | source slice, StaticFact, ContextSlice, runtime test·profiler 관찰 | `evidence.jsonl` |
| `Finding` | stable ID, 위험 분류·심각도, HypothesisContract, evidence ID, 상태축, 다음 행동·oracle, model I/O hash | `findings.jsonl` |
| `Report` | 정렬된 finding ID, coverage, scan 상태 | `report.json` |
| `UserAction` | finding별 verify·fix·accept_risk·dismiss | `actions.jsonl` |

별도 `DiagnosisPlan`, `RiskRecord`, `RuntimeEvidence` 객체는 만들지 않는다. 각각 Finding과 `Evidence(kind=runtime)`에 포함한다.

모든 객체는 `id`, `schema_version`, `content_hash`를 가진다. hash는 `content_hash` 필드를 제외한 canonical UTF-8 JSON을 key 순서로 정렬해 SHA-256으로 계산한다. 기존 record는 수정하지 않고 사용자 행동만 새 `UserAction`으로 append한다.

### 근거 분리

- `Evidence.kind=source`: 원본 source 위치와 content hash
- `Evidence.kind=static`: AST·symbol·graph fact와 producer
- `Evidence.kind=runtime`: exact command·환경·관찰값·artifact hash
- LLM request/response는 Finding의 `model_io_hash` provenance로만 남기며 Evidence나 정답으로 취급하지 않는다.

### 재현 경로

```text
Report → Finding → Evidence → ScanRun
                         └→ source SHA / exact command / artifact hash
```

실행별 디렉터리는 `runs/{run_id}` 하나이며 위 다섯 JSON·JSONL 파일만 둔다. 별도 추적성 database·service·evidence graph는 만들지 않는다.

기계 판독 가능한 적용값은 [현장 입력 명세 v18](../field-input-manifest.yaml)의 `traceability_contract`에 고정했다.

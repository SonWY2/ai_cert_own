## Question

종이 또는 클릭 가능한 결과 형상에서 한 행을 raw finding·stable risk·root-cause cluster 중 무엇으로 두고, 영향·변경 관련성·증거 강도를 상쇄하는 단일 점수 없이 어떤 tuple과 tie-break로 정렬하며, 최소 열·coverage·partial failure·다음 검증 선택·모드별 기본 진입점을 어디까지 보여줄 것인가?

## Resolution comment

- 시제품 자산: [위험 우선순위표 시제품 v1](../prototypes/risk-priority-table-v1.md)
- 한 행은 raw 관점 결과나 root-cause cluster가 아니라 stable finding ID 하나다.
- 열은 위험, 영향·조건, 변화·근거, 다음 행동 하나, 사용자 행동만 둔다.
- coverage·해석 불가 경로·동적 검증 수는 표 위 한 줄로 표시한다.
- 단일 종합 점수 없이 `severity → worsened/new 등 변화 → 근거 → 짧은 검증 시간 → finding ID` tuple로 정렬한다.
- 각 행에는 가장 좋은 다음 행동 하나와 예상 시간·확인할 결과만 제시한다.
- 정기 main은 현재 confirmed/deferred 위험, 릴리스 후보는 new/worsened 위험부터 연다.
- resolved와 rejected는 기본 표에서 숨기고 필요할 때만 표시한다.
- dashboard, chart, heatmap, cluster 화면, 복수 행동 선택지는 만들지 않는다.

기계 판독 가능한 적용값은 [현장 입력 명세 v9](../field-input-manifest.yaml)의 `risk_priority_table`에 고정했다.

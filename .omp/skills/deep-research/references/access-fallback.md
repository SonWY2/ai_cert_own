# 차단된 공개 출처의 안전한 대체

`read`가 403·봇 차단·빈 본문·JavaScript 전용 화면을 반환하면 그 페이지를 억지로 우회하지 않는다. 로그인, 유료벽, CAPTCHA, TLS fingerprint 위장, 프록시, 자동 의존성 설치는 사용하지 않는다.

## 대체 순서

1. **원출처 재발견** — 구성된 OMP `web_search`로 제목, 저자, 고유 문구, 기관명을 검색한다.
2. **공식 공개 경로** — 회사 발표·정부 문서·규제 공시·원 논문·저장소·release·공식 RSS/Atom/JSON API를 찾는다.
3. **동일 주장 독립 확인** — 원출처를 직접 읽을 수 없다면, 독립 기관의 원문을 찾는다. 재게시·복사·요약은 독립 근거가 아니다.
4. **범위 축소** — 공개 원문으로 확인 가능한 주장만 남긴다. 확인하지 못한 내용은 인용하지 않는다.

## 출처별 안전한 공개 경로

- 논문 소개·뉴스 → 원 논문, 학회·기관 페이지, 정부·회사 원문
- GitHub 소개 글 → repository, release, commit, documentation
- 소셜 게시물 → 원 기관 발표·프로젝트 release·공개 RSS. 소셜 반응 자체가 질문의 대상일 때만 공개 feed/API를 신호로 사용한다.
- Hacker News·Stack Overflow·Reddit 등 커뮤니티 → 공개 RSS 또는 문서화된 공개 API가 있을 때만 사용한다. 반응은 제품 사실의 근거가 아니라 실사용 신호로 분리한다.
- 동영상 → 공식 자막·공개 transcript가 있을 때만 사용한다. 영상 제목·설명만으로 주장하지 않는다.

## 기록 규칙

- 차단된 URL, 차단 이유, 대체 URL, 대체 출처 유형을 Evidence Ledger에 남긴다.
- 대체 출처는 차단된 원문의 내용을 자동으로 증명하지 않는다. 직접 읽은 부분만 인용한다.
- 공개 대체 경로와 독립 검증이 모두 없으면 `Unable to verify independently`로 끝낸다.

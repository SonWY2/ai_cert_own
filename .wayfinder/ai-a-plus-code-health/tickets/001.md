## Question

대상 저장소 포트폴리오, 기준 브랜치·RC topology, Python·framework·규모 분포, 실행 권한, 코드 반출 정책, 사용 가능한 실제 사례·전문가·심사 환경을 누구의 확인값과 어떤 versioned manifest로 동결할 것인가?

## Resolution comment

- 동결 자산: [현장 입력 명세 v3](../field-input-manifest.yaml)
- 대상은 Python 3.14·FastAPI·asyncio이며, `main`과 immutable PR/후보 commit의 merge-base 비교를 사용한다.
- 핵심 공개 검증은 FastAPI Users·Prefect의 end-to-end runtime 파일럿과 Langflow의 대규모 정적 확인을 사용한다. Langflow runtime은 Python 3.14 설치·대표 workload·예산·격리 조건을 통과할 때만 추가한다. 최종 판정은 공개 개발 자료와 분리한 시간 기반 공개 holdout 및 숨겨진 합성 결함으로 수행한다.
- 외부 GitHub 사례는 공개 실제 사례이지 익명 비공개 실제 사례가 아니다. 개인 과제에는 비공개 사례가 없으므로 해당 lane과 기업 비공개 저장소 일반화 주장을 제외한다.
- 평가는 프로젝트 책임자 1명이 수행한다. 실행 oracle·알려진 수정과 회귀 테스트·숨겨진 mutation manifest를 사람 판단보다 우선하고, 다수 평가자 일반화나 평가자 간 일치도는 주장하지 않는다.
- 외부 모델 API 사용 제한은 없으며 모델·prompt·예산은 실행별 고정한다. 비밀정보는 모델 입력 전에 제거한다.
- Linux Docker를 사용한다. 이는 겉보기용이 아니라 dependency·권한·재현성 경계다. 성능은 같은 host·같은 container의 profiler 미사용/사용 paired run으로 비교하고, `py-spy`의 `SYS_PTRACE`는 별도 승인 실행에서만 허용한다.

### 복잡성 감사 반영

- 현장 입력 명세를 [v3](../field-input-manifest.yaml)로 조정했다.
- 실제 end-to-end 공개 파일럿은 FastAPI Users와 Prefect 두 개가 필수다. Langflow는 대규모 정적 확인이 필수이고, 재현 가능한 workload와 실행 예산을 충족하면 runtime canary로도 사용한다.
- Python 3.14 FastAPI·asyncio 합성 fixture가 구현과 숨겨진 holdout의 중심이다.
- 기본 동적 도구는 `pytest`, `cProfile`, 표준 `asyncio` 관찰이다. `py-spy`, Scalene, Memray, VizTracer는 각기 다른 가설에 필요한 경우 하나씩 선택하는 조건부 도구다. 첫 결과가 판단 보류이고 추가 관찰 가치가 있을 때만 재승인 후 두 번째 도구를 실행한다.
- FastAPI·Starlette 별도 점수와 vLLM GPU 성능 lane은 제품 진단 가치보다 환경·계측 부담이 커 핵심 범위에서 제거한다.

## Question

고급 dataflow·CPG, graph-aware retrieval, verifier·critic·learned routing, uncertainty calibration, execution-guided test·observability, temporal change-risk 중 기본 baseline의 명시된 실패 하나를 가장 낮은 추가 권한·비용으로 보완할 후보를 최대 두 개까지 무엇으로 선택할 것인가?

## Resolution comment

활성 실험 후보는 **두 개만** 둔다.

### 1. 함수 단위 CFG + 제한된 def-use

- 목적: 분기·예외·cleanup·async cancel/await 경로의 정적 근거 보강
- 범위: 위험 가설이 생긴 함수 하나
- 비교: 같은 예산의 `F`와 `F+CFG`
- 목표: Critical/High Recall 또는 evidence precision

### 2. 근거 반증 critic

- 목적: 상위 Critical/High finding의 반대 근거와 근거 누락 탐색
- 입력: finding, 인용 근거, 이미 수집한 2-hop 문맥
- 실행: 평가 finding당 고정 LLM 호출 한 번
- 출력: `keep | reject | defer`와 counterevidence ID
- 금지: 새 finding 생성, 도구 실행, 사용자 행동 변경
- 비교: 같은 총 token·시간 예산의 `F`와 `F+critic`
- 목표: Precision 향상 또는 무근거 finding 비율 감소

두 후보 모두 별도 shadow 결과로만 저장하며 core 표와 KPI에 섞지 않는다.

Full CPG·전역 dataflow, vector DB·학습형 graph ranking, 적응형 관점 routing, 학습형 도구 routing·불확실성 보정, 다중 표본 추론은 선택하지 않는다. 현재 자료와 구현 범위에서 독립 기여를 검증하기보다 시스템 복잡성을 더 크게 늘리기 때문이다.

새 실험 후보를 추가하려면 다음 manifest version에서 기존 두 후보 중 하나를 제거해야 한다.

기계 판독 가능한 적용값은 [현장 입력 명세 v17](../field-input-manifest.yaml)의 `experimental_candidate_contract`에 고정했다.

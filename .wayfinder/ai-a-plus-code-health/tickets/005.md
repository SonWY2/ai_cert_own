## Question

2024년 이후 공식 문서·논문·재현 가능한 공개 자료를 기준으로 대규모 Python 백엔드에서 AST, 심볼/타입, CFG·데이터 흐름, Code Property Graph, 변경 영향 그래프, lexical·vector·graph 검색이 실제로 제공하는 관찰력·확장성·증분 처리 특성과 reflection·DI·dynamic import·monkey patch 한계는 무엇인가?

## Resolution comment

- 연구 자산: [대규모 Python 정적·그래프 분석 근거](../research/static-graph-evidence.md)
- 결론: 단일 정적 표현은 충분하지 않다. AST·scope·명시적 symbol/import·type coverage·lexical 검색·변경 overlay를 최소 기준선 후보로 두고, CFG·전역 dataflow·CPG·vector/graph 검색은 동일 예산 독립 기여를 입증한 뒤 승격한다.
- Python 동적 기능은 누락을 숨기지 않고 `resolved / modeled / heuristic / unknown` 근거 상태와 uncertainty ledger로 남긴다.
- 이 결론은 외부 근거 조사 결과이며 프로젝트 성능 증적이 아니다.

## Question

기본 core 밖 기능을 어떤 shadow·experimental 표식, 데이터·output lineage 분리, failure 격리, 별도 exploratory 표로 운영하고, 사전등록된 증분 효과·안전·비용·rollback 조건 중 무엇을 충족해야 기본 경로로 승격할 것인가?

## Resolution comment

실험 기능은 core와 같은 immutable input을 읽는 별도 shadow subprocess로 실행한다. core 예산·cache·위험 표를 공유하거나 변경하지 않는다.

### 결과 격리

- 별도 실행 예산과 output directory 사용
- core와 같은 finding schema를 사용하되 `EXPERIMENTAL`과 `X-...` ID 표시
- 기본 위험 우선순위표에 병합하지 않음
- core KPI와 A+ 성과 수치에 합산하지 않음
- experiment ID·기능 version, base run ID·source SHA, config·model·prompt·budget hash만 lineage로 남김

실험 timeout, 오류, 부분 결과는 실험만 중단한다. core run의 성공·실패 상태를 바꾸지 않는다.

### 승격

튜닝에 쓰지 않은 동결 자료에서 같은 예산 비교를 수행하고 다음 중 하나를 충족해야 한다.

1. 사전 등록한 목표 품질 지표 **5%p 이상 개선**
2. 품질 guardrail을 지키며 token 또는 시간 **10% 이상 절감**

Critical/High Recall 저하, unsafe·unsupported 주장, 재현 불가능한 lineage가 있으면 승격하지 않는다.

기준을 통과해도 자동 승격하지 않는다. 결과 확인 후 **다음 manifest version**에서만 `experimental → core`로 옮긴다. 끝난 final 결과에는 소급 적용하지 않는다.

승격 후 재검증에서 guardrail 또는 재현성이 깨지면 새 manifest version에서 다시 experimental로 내리고 영향을 받은 비교만 재실행한다.

기계 판독 가능한 적용값은 [현장 입력 명세 v16](../field-input-manifest.yaml)의 `experiment_isolation_contract`에 고정했다.

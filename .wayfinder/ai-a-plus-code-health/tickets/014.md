## Question

정확성·동시성·성능 가설별로 no-run, 기존 focused test, 별도 benchmark, cProfile, py-spy, Scalene 중 무엇을 어떤 순서로 제안하고, exact command·workload·환경·timeout·권한·유효기간을 묶은 승인 단위와 inconclusive 시 중단 또는 2차 수단 cascade를 어떤 사용자 흐름으로 고정할 것인가?

## Resolution comment

- 시제품 자산: [승인형 동적 검증 흐름 v1](../prototypes/dynamic-validation-flow-v1.md)
- 사용자는 전체 검증 DAG가 적힌 RunManifest를 한 번만 승인한다.
- 승인 뒤에는 DAG가 관찰 결과에 따라 다음 node를 자동 선택한다. 각 명령을 다시 승인받지 않는다.
- 승인되지 않은 도구가 새로 필요할 때만 RunManifest를 바꾸고 다시 승인받는다.

### 가설별 경로

| 가설 | DAG 경로 |
|---|---|
| 정확성 | focused pytest → 판정 |
| 동시성·async | focused pytest + asyncio 관찰 → hang 또는 stack 필요 시 py-spy → 판정 |
| 성능 | profiler 없는 workload 반복 → 저하 재현 시 cProfile → Python/native/system 구분 필요 시 Scalene → 판정 |
| 실행 불가 | `no-run` → `deferred` |

성능 수치는 반드시 profiler 없는 반복 실행에서 먼저 확인한다. cProfile은 재현된 저하의 hotspot을 찾는 데만 쓴다. profiler 결과 자체를 benchmark로 사용하지 않는다.

### 승인과 중단

RunManifest에는 snapshot, node별 exact command·workload·도구·분기 조건, 환경, 전체 timeout·CPU·memory, network, 쓰기 경로, 판정 oracle을 담는다. 승인은 해당 manifest hash의 실행 한 번에만 유효하다.

DAG는 다음 경우 멈춘다.

- oracle이 가설을 확인하거나 기각함
- 다음 node 조건이 성립하지 않음
- 전체 timeout·resource 한도 도달
- 승인된 node를 모두 사용함

종료 상태는 `confirmed | rejected | deferred`만 사용한다. profiler를 동시에 실행하거나 승인된 DAG 밖 도구를 자동 실행하지 않는다.

기계 판독 가능한 적용값은 [현장 입력 명세 v12](../field-input-manifest.yaml)의 `dynamic_validation_dag`에 고정했다.

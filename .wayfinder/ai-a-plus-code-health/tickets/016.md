## Question

공개 실제·합성·익명 실제·정상·unsafe 사례를 어떤 역할과 strata로 받아들이고, license·기밀·재식별 gate, repository-family·temporal split, 공개 patch·사전학습 오염 audit, root-cause·영향·상대 우선순위의 blind adjudication과 불일치 중재를 어떤 versioned protocol로 고정할 것인가?

## Resolution comment

평가 protocol은 `evaluation-protocol-v1` 하나로 관리한다. 자료는 개발용 공개 파일럿과 최종 검증 자료를 섞지 않는다.

### 자료 역할

| 자료 | 역할 | 최종 성과 수치 |
|---|---|---:|
| 고정 공개 저장소 파일럿 | 개발, 재현, 예비 결과 | 제외 |
| 숨겨진 합성 holdout | 통제된 결함·정상 코드·unsafe 요청 평가 | 포함 |
| 개발 종료 뒤 시간 기반 공개 holdout | 실제 공개 코드 일반화 확인 | 포함 |

익명 비공개 사례는 사용하지 않는다. 합성 fixture는 프로젝트 소유 자료, 공개 저장소는 revision과 license가 기록된 자료만 받는다.

### 분리와 오염 통제

- 같은 저장소·template family는 하나의 split에만 둔다.
- near-duplicate를 개발 자료와 최종 자료에 나누지 않는다.
- 개발이 끝난 뒤 시간 cutoff와 최종 case ID·hash를 동결한다.
- 공개 코드의 사전학습 포함 여부는 `unknown_or_likely_exposed`로 기록하고 contamination-free를 주장하지 않는다.
- 공개 patch는 보조 근거일 뿐 완전한 정답으로 사용하지 않는다.

### 정답 판정

모델 결과를 보기 전에 case별 gold record를 봉인한다. 포함 값은 case·family ID, snapshot SHA, 실행 oracle, 기대 invariant·실패, root-cause symbol, 영향·상대 우선순위다.

정답 우선순위는 다음과 같다.

1. 실행 가능한 behavior oracle
2. 알려진 regression test
3. 숨겨진 mutation manifest
4. 고정된 독립 LLM judge의 의미 일치 판정

LLM judge는 실행 oracle·regression test·mutation manifest를 뒤집지 않고, 봉인된 정답과 위험·근거·다음 행동의 의미 일치만 판정한다. judge에는 평가 arm을 공개하지 않는다.

상위 근거끼리 충돌하고 해결할 수 없으면 결과를 본 뒤 정답을 고치지 않고 해당 case를 집계에서 제외하며 이유를 남긴다.

숨겨진 합성 holdout에는 결함 사례뿐 아니라 정상 코드 오탐 사례와 승인 없는 실행·Critical/High 부당 기각 사례도 포함한다.

최종 보고서는 합성 holdout과 시간 holdout 결과를 먼저 따로 제시한다. 사람 평가는 수행하지 않으며 LLM judge의 모델·prompt·교정 정확도와 한계를 공개한다.

기계 판독 가능한 적용값은 [현장 입력 명세 v15](../field-input-manifest.yaml)의 `evaluation_dataset_contract`와 `evaluation_judge`에 고정했다.

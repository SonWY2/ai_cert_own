## Question

파일·설정·metadata·AST·source graph 읽기 중 자동 허용 범위, import·test 수집·test·benchmark·profiler·process attach 중 건별 승인 범위, network·filesystem·secret·모델 전송·저장·반출의 금지 범위를 어떤 capability와 data-class matrix로 고정할 것인가?

## Resolution comment

과도한 파일별 승인·명령별 승인·세분화된 자료 등급·RBAC·별도 redaction 절차는 만들지 않는다. 정책은 **자동 정적 읽기 + RunManifest 1회 승인 + 명시적 금지** 세 구간으로 고정한다.

### Capability 경계

| 구간 | 허용 범위 |
|---|---|
| 자동 정적 읽기 | 선택한 immutable repository snapshot 안의 source·config·lockfile·metadata·Git diff·AST·symbol/import·source graph |
| `RunManifest` 1회 승인 | dependency 설치, import, test 수집, test·benchmark·profiler, 설정한 외부 모델 API, 컨테이너 내부 process attach |
| 금지 | snapshot 밖 읽기, symlink escape, 선언 경로 밖 쓰기, host·production process attach, source 수정, patch·merge·release·deployment |

`RunManifest`는 snapshot, 명령·workload, 선택 도구, 실행 한도, network·쓰기 경로, 모델과 전송 자료를 한 화면에서 보여준다. 한 번 승인하면 그 실행 전체에 유효하다. snapshot 또는 manifest hash가 바뀔 때만 다시 승인한다.

### 최소 자료 분류

| 자료 | 자동 읽기 | 외부 모델 전송 | 보관 |
|---|---:|---:|---|
| `project_data`: snapshot 전체와 AST·graph·log·profile·evidence | snapshot 내부 허용 | 승인된 RunManifest 안에서 전체 허용 | source는 원래 snapshot, raw 실행 자료는 로컬 임시 보관, 구조화 증거는 재현 기간 보관 |
| `harness_credentials`: 모델 API key·컨테이너 credential | 분석 입력 아님 | 금지 | snapshot 밖 환경 변수로만 주입 |

현재 평가 자료가 공개 저장소와 합성 fixture이므로 별도 코드 반출 분류기·secret scanner·snippet별 승인은 구현하지 않는다. 모델 provider·version·prompt hash는 실행 재현을 위해 RunManifest에 남기되, project data의 세부 항목을 나눠 전송 통제하지 않는다.

target workload network는 기본적으로 끄되 workload 자체가 network를 필요로 할 때 RunManifest에 한 줄로 선언한다. analyzer의 dependency 설치와 모델 API 호출도 같은 manifest에 포함한다.

원본 log/profile은 결과 확인이 끝날 때까지 로컬 격리 workspace에 둔다. 장기 증적은 `Evidence(kind=runtime)`, 입력·결과 hash, 판정, 비용만 보관한다.

기계 판독 가능한 적용값은 [현장 입력 명세 v18](../field-input-manifest.yaml)의 `execution_capabilities`, `code_and_evidence_policy`, `traceability_contract`에 고정했다.

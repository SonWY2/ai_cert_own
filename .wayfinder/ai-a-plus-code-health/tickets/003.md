## Question

현재 문서의 AST·Code Graph·다관점 LLM·HypothesisContract·profiler·DAG 주장을 미검증 가설, 기본 채택 후보, 실험 후보 중 어디에 두고, 각 제품·A+ 주장을 유지·강등·기각하는 최소 증거 종류와 반증 조건을 무엇으로 고정할 것인가?

## Resolution comment

### 판정 모델

기술의 **시스템 역할**과 **증명 상태**를 서로 독립된 축으로 관리한다. `core`는 구현 우선순위이지 성능이 입증됐다는 뜻이 아니다.

```text
role = core | experimental | excluded
evidence = external_fact | project_hypothesis
         | preliminary_project_result | validated_project_result | invalidated
```

현재 프로젝트에는 코드·실행·최종 holdout이 없으므로 `validated_project_result`는 **0건**이다. 공식 문서와 논문은 도구의 기능·원리·한계를 뒷받침하는 `external_fact`일 뿐 본 프로젝트 성과가 아니다.

### 초기 역할

| 역할 | 구성 |
|---|---|
| `core` | 결정론적 AST·scope·symbol/import·lexical, unresolved를 보존하는 bounded typed Code Graph, fixed-five LLM 기준선, HypothesisContract·ExecutionPolicy·Evidence Gate, 선택형 pytest·cProfile·asyncio 검증, 결정론적 병합과 fixed-chain 비교군을 가진 bounded DAG |
| `experimental` | 전역 dataflow·CPG·vector·추가 graph 확장, 적응형 관점 routing, evidence-cited critic, 학습형 도구 router·불확실성 보정, 다중 표본 추론, py-spy·Scalene·Memray·VizTracer, 조건부 Langflow runtime |
| `excluded` | 자유형 agent swarm, 반복 debate, LLM-only graph, profiler 항상 실행, 자동 release gate, vLLM GPU 성능 lane |

### 최소 증거

| 허용 주장 | 최소 증거 |
|---|---|
| 도구가 특정 기능을 제공한다 | version이 고정된 공식 문서·source 또는 1차 연구 |
| 기능이 구현됐다 | 실제 source, 변경 계약 test, 정상·실패 end-to-end trace |
| 구성요소가 독립 기여한다 | 동일 `B_run`·권한·입력의 제거 실험, 품질·비용·안전 guardrail, frozen final holdout |
| 위험이 실행으로 확인됐다 | 동일 snapshot의 immutable `Evidence(kind=runtime)`, workload·환경·명령 hash, 독립 oracle |
| 시스템 권고 품질이 개선됐다 | plain LLM 대비 full system final holdout에서 `ValidNextVerificationRecommendation@20m` +30%p와 Critical/High 부당 기각 절대 0건 |
| A+ 수준이다 | 최종 holdout 결과, rubric 1:1 증적 추적, 탈락 조건 공백 0건 |

### 강등·기각

- 동일 예산 비교에서 품질·비용·안전 중 사전 등록한 독립 기여가 없으면 `core`에서 `experimental` 또는 `excluded`로 내린다.
- source/evidence hash 불일치, 숨겨진 oracle·holdout 노출, unsafe run, full system의 Critical/High 부당 기각은 해당 결과를 `invalidated`로 만든다.
- 파일럿은 표본·튜닝 노출·불확실성을 밝힌 `preliminary_project_result`로만 보고한다. A+ 달성 수치에 합산하지 않는다.
- hash·schema·권한·상태 전이 gate처럼 금지 상태를 결정론적으로 막는 구성은 Recall 향상이 없어도 허용 가능한 overhead와 위반 방지 증거가 있으면 `core`에 남을 수 있다.
- 패치 통과, 외부 논문 수치, vendor benchmark, 구현 완료만으로 진단 우월성이나 시스템 권고 품질 주장을 허용하지 않는다.

기계 판독 가능한 적용값은 [현장 입력 명세 v18](../field-input-manifest.yaml)의 `claim_policy`와 `traceability_contract`에 고정했다.

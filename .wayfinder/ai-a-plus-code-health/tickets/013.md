## Question

지원 범위의 중요 위험을 위해 AST·symbol·import에서 CFG·type·dataflow·graph까지 필요한 최소 fact 집합은 무엇이며, property graph·edge table·on-demand traversal·graph 없음과 lexical·symbol·vector·long-context retrieval 중 어떤 조합이 비용·불완전성·재현성 면에서 기본 baseline이 되어야 하는가?

## Resolution comment

기본 정적 경로는 Python 표준 `ast`·`symtable`, SQLite node·edge 표, lexical·symbol·최대 2-hop graph 탐색으로 고정한다. 별도 graph database나 vector database는 사용하지 않는다.

### 수집할 최소 fact

- node: file, module, class, function/method
- edge: defines, imports, 정적으로 해석되는 calls·inherits
- AST 표시: async/await, task 생성, try/except/finally, context manager, raise/return, decorator
- 각 edge의 해석 상태: `resolved | unknown`

여기서 typed graph는 Python type을 전체 추론한다는 뜻이 아니라 node·edge 종류가 명시돼 있다는 뜻이다. 동적 call을 추측해서 edge로 만들지 않는다.

### 문맥 검색

변경 코드, stacktrace 또는 사용자가 지정한 symbol을 seed로 삼고 다음 순서로 source slice를 모은다.

1. 정확한 symbol
2. 변경 파일과 lexical 일치
3. 1-hop graph 이웃
4. 2-hop graph 이웃

각 slice에는 file, symbol, line range, source hash를 붙인다. 같은 입력은 같은 순서가 되도록 결정론적으로 정렬한다.

### 기본 경로에서 제외

- CFG
- 전역 dataflow
- 전체 프로그램 type 추론
- CPG
- vector database와 embedding 검색
- 학습형 graph ranking
- 저장소 전체 long-context 입력

이 기능들은 기본 구현에 넣지 않는다. 후속 실험에서 같은 예산으로 독립 기여를 보인 경우에만 승격한다.

Code Graph의 효과는 `lexical+symbol` 비교군과 `lexical+symbol+2-hop graph` 제안군을 같은 입력·모델·예산으로 비교한다. 이 결과가 나오기 전에는 graph 우월성을 주장하지 않는다.

기계 판독 가능한 적용값은 [현장 입력 명세 v11](../field-input-manifest.yaml)의 `static_analysis_baseline`에 고정했다.

### 후속 보강 결정

심사에서 정적 분석의 기술 깊이와 독립 기여를 보여주기 위해 **함수 단위 CFG + 제한된 def-use**를 실험 경로로 추가한다. 기본 경로에는 넣지 않는다.

- 대상: 정확성·동시성·자원 수명 가설이 생긴 함수 하나
- CFG: normal·branch·exception·finally edge
- dataflow: parameter·assignment·use·return·raise의 함수 내부 def-use
- 확인 대상: 미초기화·stale 값, 종료 경로 cleanup 누락, 예외 경로 공백, async cancel·await 경로 공백
- 제외: 함수 간 dataflow, heap·alias 분석, 동적 call 해석, 저장소 전체 CFG
- 검증: 같은 예산에서 기본 경로와 `기본 경로 + 함수 단위 CFG/def-use`를 제거 실험으로 비교

Critical/High Recall 또는 evidence precision이 개선되고 비용·안전 기준을 지킬 때만 core 승격을 검토한다. Full CPG와 학습형 graph ranking은 학습 자료·구축 비용 대비 직접 근거가 부족하므로 제외 상태를 유지한다.

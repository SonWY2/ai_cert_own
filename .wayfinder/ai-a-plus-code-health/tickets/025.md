## Question

사람이 평가 사례를 만들거나 판정·실측을 수행하지 않는다는 새 사용자 제약 아래, 기존 기획서의 사람 KPI와 동결 v22의 무인 평가 계약을 어떻게 구분하는가?

## Resolution comment

사용자는 이제 본인 준비나 사람의 직접 수행을 원하지 않는다. 2026-09-24의 사람 실측 선택은 철회한다. v22의 `human_evaluation: none`과 `prohibited_human_claims`를 유지하고, 원 기획서의 사람 진단 시간 50%·재작업 30%·리뷰 생산성 향상은 **미달성·주장 금지**로 분리한다. 원 기획서가 이미 제출됐는지 확인되지 않았으므로 사람이 측정한 성과로 자동 지표를 재명명하거나 기존 제출본을 조용히 수정하지 않는다. 심사에서 기획서 수정이 허용되지 않으면 약속 불일치가 남는다.

최종 평가의 80개 적격 사례는 분리된 자동 평가 절차가 진단보다 먼저 만든다. 결함/수정판 차등 실행·알려진 회귀 테스트·숨긴 변이 명세 순으로 정답을 확인하고 봉인한다. 진단 모델에 정답·봉인 키를 주지 않는다. 다른 모델 계열·고정 버전의 LLM은 군명을 가린 결과의 원인·근거·다음 행동 의미 일치만 판정하며, 실행 정답을 덮어쓰지 못한다. 판정 모델 계열이 확인되지 않거나 실행 oracle이 없으면 독립 평가 완료로 표시하지 않는다. 같은 에이전트 모델의 다중 역할·블라인드 문장만으로 외부 독립성, 사람 KPI, 인증 등급을 입증할 수 없다. [무인 측정 계약](../../../docs/evidence/01-kpi-measurement-framework.md)과 [비교 계획](../../../docs/evidence/02-benchmark-and-ablation-plan.md)에 설계·미실측을 구분해 기록했다.

자동화는 실행 권한을 만들지 않는다. 대상 코드 실행/모델 전송은 현 v22의 정확한 RunManifest 소유자 승인·Docker 격리 조건을 계속 요구한다. 사용자의 무인 선호는 승인이 아니며, 이 조건을 못 채우면 개발용 정적 분석과 제한된 합성 사례만 보고하고 파일럿·최종 우월성·A/A+ 주장을 중단한다. 평가 소프트웨어/정답 세트/모델 공급·실행 환경은 이 티켓을 닫았다는 이유로 준비된 것이 아니다.

## Question

전체 스캔과 변경분 스캔이 어떤 source hash·환경·분석기 버전·그래프 조각·모델 결과를 재사용하고, invalidation 경계·stale 표시·주기적 clean replay·full-vs-delta 동등성 표본 검증·성능 예산을 어떻게 고정할 것인가?

## Resolution comment

증분 점검은 같은 immutable snapshot을 분석하는 최적화다. `impact`는 변경 Python 파일과 해석된 역방향 import·call·inherit 이웃에 한정한 **부분 관찰**이다. 기준 브랜치의 full inventory는 비교에 보존하되, 범위 밖의 기존 위험을 사라진 위험으로 표시하지 않는다. 미관측 또는 해석 불가 의존 경로는 비교 `unknown`이다. `resolved`는 대상 범위를 완전히 분석한 경우에만 허용한다.

- 재사용 단위는 파일별 `ast`·`symtable` 정적 사실이다. 키는 source bytes SHA-256, 정규화된 저장소 상대 경로·source root, Python parser 버전, 분석기·설정 버전이다. import 대상·graph edge·문맥 slice는 현재 snapshot에서 다시 구성한다. 파일 이동·삭제 또는 의존 파일 변경 시 이전 graph 조각은 재사용하지 않는다.
- cache hit도 현재 snapshot의 source hash를 다시 확인한다. `ScanRun`에는 파일별 cache key·artifact hash·생성 run, hit/miss·무효화 이유, 비교 범위·완전성, clean replay run ID를 남긴다. 재사용한 사실은 현재 run에 속한 새 `Evidence`로 기록한다. 실행 관찰, LLM 출력, 과거 Finding·Report·Evidence ID는 재사용하지 않는다.
- main 주간 full은 cache 없는 clean replay로 실행한다. 후보 `impact`는 파일럿에서 같은 SHA·범위·분석기·모델·prompt·예산·환경의 clean full과 짝지어 비교한다. 운영 중에는 저장소마다 매주 첫 후보를 같은 방식으로 표본 확인한다. 비교 대상은 관측 범위 내 정렬된 위험 identity·분류·심각도·상태·우선순위·근거의 의미 내용과 source hash·coverage다. run 전용 ID·시각·비용은 제외한다. 불일치나 hash 오류는 증분 결과를 무효화하고 clean full로 재실행하며 원인 확인 전 해당 저장소의 cache를 중단한다.
- `impact` 밖의 기존 위험은 기준 inventory에 남기되 대상에서 미확인으로 표시한다. 최소 보고서 전에 예산을 넘으면 `rejected`; 보고서 뒤 일부 경로가 중단되면 `accepted`에 누락 경로와 해당 finding의 `deferred`/비교 `unknown`을 표시한다.
- scan 시간·메모리·cache 수치는 파일럿에서 p50/p95 wall time, peak RSS, hit rate, full 대비 delta 비용, 동등성 위반을 측정한 뒤 거절 한도를 동결한다. 최종 평가 20분은 전체 파이프라인 상한이지 scan의 별도 고정 한도가 아니다.

적용값은 [현장 입력 명세 v22](../field-input-manifest.yaml)의 `incremental_scan_contract`에 기록했다.
